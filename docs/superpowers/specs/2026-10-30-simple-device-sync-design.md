# 简化设备双向同步

## 已确认的目标
- PC 开启局域网同步后展示二维码，手机扫码即可发起连接和双向同步。
- 手机也可等待连接并展示局域网 IP:端口；PC 输入地址，手机确认后开始双向同步。
- 跨网域使用真实 Syncthing；首次配置管理 API Key，由应用自动授权设备和共享目录。
- 用户已确认：可以先在同一局域网完成配对，之后跨网自动同步；本次不增加从未同网设备的首次远程配对。
- 保留 Android、iOS、macOS、Windows；不再要求普通用户复制多轮配对文本、管理同步空间或导出 node.json。
- 既有 HTTPS 节点继续可用，放入高级设置，不改动现有用户配置。

## 现状
- 已有设备身份、加密邀请、成员授权、TLS 指纹和历史合并；局域网目前仅允许已配对设备拉取。
- 现有一次同步只发布本地文件并拉取对端，不等于双方都收到；自动调度目前仅覆盖 HTTPS 节点。
- Syncthing 只有平台接口预留，未安装、启动或接入真实引擎；扫码功能也尚未接入。

## 局域网体验
- 主界面显示“局域网同步”开关、连接设备、等待连接和已连接设备状态。
- PC 等待连接时展示二维码及 IP:端口；手机提供扫一扫；两端均可手动输入地址。
- 手机等待连接时展示真实网卡地址和端口；多网卡允许选择，不展示 0.0.0.0 作为连接地址。
- PC 二维码包含短时、单次配对票据、连接地址和服务端身份绑定信息，不含长期私钥。
- 手机扫描后显示 PC 名称并确认连接；PC 开启二维码邀请即授权持有该次票据的加入方。
- 手输地址时 PC 显示本次连接短码，手机弹出请求及短码；手机用户核对后点击允许。
- 不再要求复制邀请、应答、确认、授权包；这些消息由连接自动交换。
- 拒绝、取消、超时后关闭本次配对会话；已配对设备再次连接无需重复配对。
- 连接成功后双方自动交换历史，再持续双向同步；显示连接中、等待确认、同步中、已同步、离线或失败。

## 配对和数据边界
- 配对端点只在明确开启等待连接时存在，限时、限量；不得放宽既有数据端点的成员鉴权。
- 复用现有身份签名和授权包。扫码必须验证票据和 TLS 身份绑定；地址连接必须用用户核对的短码绑定会话。
- 不得通过无条件调用 confirmShortCode 绕过认证；新的确认方式须有明确授权状态和中间人攻击验证。
- 只有成员状态和密钥安全持久化成功、对端确认收到后才显示连接成功。
- 两端均无同步空间时自动创建一个；只有一端已有空间时复用该空间，逻辑授权方不受网络发起方向限制。
- 未加入空间的设备保留现有便签、事项、标签和附件，通过现有初始基线合并。
- 两端已有不同同步空间时阻止直接合并并明确解释；不得清空数据或覆盖密钥。跨空间迁移不在本次范围内。
- 配对后交换经认证的监听地址，双方使用现有 LAN 拉取与自动调度；本机发布量不得当成对端接收成功。
- 修改去抖、断线重试、设备撤销和暂停沿用现有机制；切网后更新地址，所有监听、轮询和任务均可停止。
- 手机前台同步、恢复前台补传；不承诺 iOS 挂起或应用被杀后的持续实时同步。

## Syncthing 配置体验
- 首次启用填写“管理域名/地址＋端口”和 API Key；输入明确指向 REST 管理服务，不混用同步传输端口。
- 管理请求公网使用 HTTPS；证书正常验证。域名输入可自动补全 https://，不要求用户理解协议细节。
- 通过 REST 验证 API Key，取得服务端 Device ID 和配置；应用自动添加本设备及专用共享目录。
- 后续保留地址和连接状态，不重复输入 Key；设备的 Syncthing 身份和已获授权配置持久保存。
- 一次性配置指当前设备首次启用；不得在二维码、日志、普通配置或同步目录中散发服务器管理 Key。

## Syncthing 实现与权限边界
- Syncthing 是传输层：两端先完成 SeqPoint 同一空间配对，不能用 NAS 管理 Key 替代内容解密密钥或空间授权。
- 调用现有 SecureStore 保存 API Key；错误和日志脱敏，未授权、证书错误、端口错误、传输不可达分别提示。
- REST 自动登记真实引擎 Device ID；读取/发现传输地址，管理端口不冒充 BEP 同步端口。
- 只建立 SeqPoint 命名空间下的专用 Folder ID 和目录；服务端使用其默认文件夹根下的新子目录。
- 只增改当前空间需要的授权；保留服务端其他设备、文件夹、设置及用户数据，不能整份配置覆盖。
- 撤销时只撤销对应 SeqPoint 共享；其他文件夹仍使用的 Syncthing 设备不能被删除。
- 管理 Key 仅用于配置，正常数据传输使用 Syncthing 设备身份；拒绝 Key 后不得伪造连接成功。
- 同步的是现有协议的加密不可变日志、检查点、附件块；不复制 SQLite、锁文件、设备私钥或 Keychain。
- 文件到达后仍走现有签名、成员权限、去重、冲突和检查点验证；Syncthing 传输成功不等于应用已合并。
- 保留 NAS 为存储设备：一端上传后可离线，另一端稍后获取；不把纯中继服务器当作存储节点。
- 实现真实四端引擎宿主：桌面受控进程，Android 原生宿主，iOS 内置原生 framework。
- 优先复用 Syncthing 官方引擎及可审查的桥接代码；具体版本、许可、分发校验及四端构建必须先验证，不能自行伪造兼容协议。
- 先验证原生宿主可编译、启动、停机和传输，再开放对应 UI；不得用空实现或 isSupported=true 交付。
- iOS 引擎随安装包编译，不能运行时下载可执行代码；桌面和 Android 的交付形式由兼容性与现有宿主约束确定。
- 新增扫码权限和原生引擎需要完整安装包更新，不能仅依靠 Shorebird Dart 补丁。

## 落地顺序及验证
1. 复用现有协议完成网络配对、局域网地址展示和二维码/扫码；实现两种发起方向。
2. 接入双端自动调度、地址持久化、重连、暂停及前后台行为；验证现有数据不丢失。
3. 完成四端真实 Syncthing 引擎最小传输验证，再接入 REST 自动授权和加密目录适配。
4. 执行桌面/移动配对与双向同步验证、原版 Syncthing 集成验证和四端构建。
- 每次产品代码改动按 .codex/TODO.md 拆为不超过 50 行的原子步骤，只有一个步骤进行中，逐文件校验。
- 网络协议测试覆盖取消、超时、过期/重复票据、错误指纹、短码不匹配、未确认连接、授权保存失败和设备撤销。
- 双向测试必须证明 A 创建→B收到、B修改→A收到，及断网重连后无丢失、无重复、无错误的“已同步”。
- 数据测试覆盖两端原有未同步数据、同空间重连及不同空间明确拒绝，不能把本机发布计数当作双向验收。
- 管理 API 测试覆盖错误 Key、仅改本应用目录、保留无关配置、重复配置幂等和部分失败可恢复。
- 使用真实 Syncthing 实例验证加密文件传输及应用合并；Mock REST 成功不能代替真实同步。
- 四端编译及插件权限检查通过后，区分模拟器/桌面自动测试与尚需真机验证的相机、网络权限、后台限制。
- 本次授权为实现与验证；不自动修改已发布的 v0.1.0 标签，不自动发布新版本或推送热补丁。

## 待落地的技术选择
- 二维码/扫码库只引入完成该功能所需的最小依赖，复用项目设置组件和错误提示。
- 原生桥接方案由实现者验证后选择；如官方引擎实际无法在某平台交付，应报告具体阻塞，不能静默缩减四端范围。
- 不增加自动合并不同同步空间、修改 NAS 其他共享或手机常驻后台等未授权行为。
