# 本机同步服务与首版交互约定

依据：已批准的六阶段设计、同步V1与成员签名规则；本页固化常规接线选择，不增加服务器或备份格式。

## 入口与状态
- 主引擎独占AppSyncService，子便签引擎只写共享DB事务Outbox。
- 打开应用/设置不读取或创建身份、Vault或网络监听；点击“准备本机”才通过系统安全存储加载身份/TLS材料。
- 用户显式创建同步空间，或接收已确认配对的空间；安全记录写入回读成功且身份/密钥核验后才建立业务基线。
- 监听与同步均为显式动作；地址使用局域网字面IP及实际端口，连接信息目前只在本次页面保留。
- 本轮接收、本机已发布、等待对象/历史分别展示；发布文件或TLS可达不代表对端收到，没有ACK事实不显示已同步。
- 本地目录、云中转和Syncthing仍禁用，不宣称已安装/会下载或取走即删除。

## 手动配对码
- 首版不新增摄像头/扫码依赖；在可信的人工通道交换不透明配对码。
- 顺序为邀请、响应、双方短码核对及确认凭据、主机授权交付、接收机安全保存。
- 不同用途代码不能混用；严格版本/规范base64url/字节及嵌套深度限制，日志不打印代码。
- 短码需输入另一台显示值；只有本机确认不等于双方确认，不允许UI开关绕过协议。
- 只有用户点击复制才写系统剪贴板；无自动复制/发消息，测试使用fake剪贴板。
- 授权交付绑定真实完成会话的检查点hash与完整双端身份；安全写回读失败不输出已保存或可用状态。
- 离页/过期只取消本页持有邀请与会话，不取消后来新页面的会话；恢复忙时所有动作禁用。

## 持久与生命周期
- 控制文件只从已安全保存的已验事实构造，不能扫描搬运目录自报信任；结构坏文件整拒，签名坏后缀可保存其先前已验前缀后阻断。
- 控制通道成员鉴权不依赖当前Epoch key；业务依赖当前授权及有效key，不能退回旧key发新业务。
- v2安全记录保留经anchor/已验facts/isolated证明的历史key，兼容v1；旧v1已丢失的key不反推、不伪造。
- 当前peer已有完整持久事实的精确旧段封口仅更新元数据/水位；未知/新增/变更旧事实仍等待且不导入。
- 远端业务提交后对账提醒，再以Scope revision刷新主界面；排程失败保留业务及错误，不回滚已提交数据。
- 恢复/退出先停止接受工作，排空控制保存、运行时、原始超时任务、发布/ACK和提醒队列，再关闭旧DB。
- 恢复成功或回滚重开后创建新服务/对账实例；Root卸载中恢复由外层finally收口，不能与异步任务抢关DB。
- 退出排空失败保留主窗与DB连接；不强制丢弃待发操作。

## 恢复身份与控制冲突
- 恢复状态仍关闭同步；显式开始恢复每次生成全新签名/交换身份，安全记录追加保存旧active及候选私钥，不覆盖审计材料。
- identity v2兼容v1，单条记录保存最多64身份/64KiB历史、写前容量门槛及写后回读；已有DB writer只精确匹配已安全保存的身份/成员记录，缺失即关闭。
- 恢复flag存在时重开不自动复用可能曾提交的候选；用户须再次显式生成新身份，防止重复恢复后复用发布writer。
- 新身份成员记录按设备ID隔离，旧记录保留；双方短码确认、Epoch解封/检查点核验及安全保存全部成功后，才原子提交新writer/基线与清恢复flag。
- 无跨SQLite/SecretStore原子性假设；DB提交前私密材料已安全存在，提交后重开按DB writer定位，不依赖第二次私密“激活”写。
- 控制冲突恢复保留原业务及旧控制审计；host候选须同Vault、新授权域、超过所有已观察分支Epoch及未用过的新key，所选设备重新确认。
- host只有真实完成双方配对并封装绑定检查点后才可安全保存新控制；guest必须真实解封同一绑定。普通文件或按钮开关不能清conflict。
- 本轮等待列表只列Outcome实际`waitingPeers`完整ID；没有设备名/具体原因字段，不补推断。

## 设备撤销
- 当前可用成员可撤销另一active设备，无owner特权或自撤销；设置显示完整公开ID，标准确认保留原目标全公钥/TLS与成员版本。
- 确认后如恢复/冲突/忙或版本已变，拒绝并要求重新核对；不自动换成新版本重试，也不承诺远程删除旧数据。
- 服务在签名await前后检查当前私有控制、身份/父head/目标与实际DB writer/基线；只将事件追加到已安全保存的自有members文件，不扫描搬运目录。
- 撤销自动使用fresh新Epoch及精确剩余接收者封装；controller写入回读成功后才激活新状态。其他成员同步控制后取得新key，被撤成员不能从本机继续取得新数据。
- 失败阻断授权，旧控制/密钥审计、业务/Outbox/媒体bytes不清理；回读失败后须重新核验已保存记录。成功取消旧配对，历史Epoch key仅用于认证旧历史，不退回旧key发布新事实。

## 明确未完成的验收
- 首版为手动同步，非后台自动轮询，也不把本机测试当真实双设备验证。
- 恢复后新身份重新配对及显式冲突恢复已完成本机验收；未见证旧历史仍等待，可信初始化没有新合同，不以旧writer或猜测水位绕过。
- PRD AC-008设备撤销已完成本机接线及临时三实例真实TLS验收；不提供无必交付依据的独立rotate按钮。
- iOS/Android实际PKCS12、Keychain、局域网权限及真实音频/保存选择器仍待真机；编译不等于运行验收。
- SQLite快照不包含库外附件；媒体软删保留bytes，可携带加密备份按原设计后置。
