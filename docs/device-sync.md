# 局域网与 Syncthing 同步

## 首次配对

1. 手机和电脑接入同一局域网，打开「设置 → 同步 → 连接手机或电脑」。
2. 电脑点击「等待设备连接」，手机点击「扫一扫」扫描电脑的二维码。
   也可让手机等待连接，把手机显示的 `IP:端口` 填入电脑，点击「连接此地址」。
3. 核对两端显示的短码一致，在等待连接的一端点击「短码一致，允许同步」。
4. 两端开启「局域网自动双向同步」，随后修改会自动交换，无需重复配对。

配对期间保持页面打开；配对完成后可以离开页面。手机同步时需保持应用在前台。
首次扫码需要相机权限，iOS 需要允许本地网络访问；电脑防火墙需允许本地连接。
设备的局域网地址改变后，可在连接页重新连接。不要用公网地址代替局域网邀请。

## 通过自己的 Syncthing 节点跨网同步

先完成上述局域网配对，以便两台设备共享序点的加密身份。
然后在每台客户端的「Syncthing 跨网同步」中各配置一次：

1. 在 NAS 的 Syncthing 管理界面取得 API Key。
2. 填入 NAS **管理 API** 的域名和端口，例如 `nas.catorg.cc:443`。
   此示例要求该 HTTPS 端口确实转发到 Syncthing 管理 API；仅有 DNS 域名还不够。
   若管理界面直接提供 HTTPS，可填写其实际端口，如 `nas.catorg.cc:8384`。
3. 首次填入管理 API Key，点击「保存并授权」，开启跨网同步。
   应用自动登记本机 Syncthing 设备并共享本资料库的加密目录。
4. 另一台已配对设备配置同一 NAS。之后无需同时在线，NAS 保留待接收的数据。

不带协议的地址按 HTTPS 处理；公网管理 API 必须使用有效 HTTPS 证书，
因为请求携带能修改 Syncthing 配置的 API Key。内网 IP 可显式使用
`http://192.168.1.10:8384`。API Key 仅保存在客户端安全存储，同一地址留空可保留已存密钥。
不要把 API Key 发到聊天、提交到仓库，或把它当作序点的设备配对密钥。

管理端口与文件传输端口不同：这里不能填 `22000` 代替管理地址。
NAS 的 Syncthing 传输监听端口、网络发现或中继也必须可用；只开放管理页面并不能传输文件。
应用按 NAS 的监听配置连接传输端口，不会把 API Key 放进传输地址。

新共享目录位于 NAS 配置的默认目录下的 `SeqPoint/seqpoint-…`；
没有默认目录时使用 Syncthing 服务用户的主目录。请确保该位置可写，容器部署时持久化该目录。
目录里只存序点加密后的同步数据，不是可直接打开的原始笔记数据库。
无需为此功能部署序点 HTTPS 中转节点，也无需手工复制 `node.json`。

「同步附件和录音」控制原文件传输，也会使用移动网络；文字内容按正常同步处理。
暂停同步会停止当前原生传输，恢复后继续交换。手机进入后台会暂停，回到前台后继续。
恢复备份、身份冲突或撤销设备时，先按「恢复同步／高级同步设置」中的提示处理。
本机已上传不代表另一端已接收；重要数据仍需独立备份。
